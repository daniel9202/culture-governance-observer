# 文件同步

這個 repo 的每個 AI 開工前都讀文件，過時的段落會讓它們照舊流程做事。這個流程找出過時段落、給使用者確認、再修改。

`AGENTS.md` 規定 `docs/` 與 `AGENTS.md` 只在使用者明確要求時修改，所以分兩段：先給清單，使用者逐項同意後才動手。

## 第一段：找出來

1. `git fetch origin`，確認目前工作目錄的內容不比 `origin/beta` 舊。比較舊的話先告訴使用者，同步之後再查，否則會把已經修過的段落再列一次。
2. 派給 `docs-checker` 子代理。使用者有指定檔案就寫進交辦訊息。
3. 檢查子代理的清單：每一項自己打開檔案核對行號與現有文字，確認它說的「實際值」是對的。核對不出來的項目拿掉或改標「待確認」。
4. 把清單給使用者，依檔案分組，每項編號，寫明現有文字、與什麼不符、建議改成什麼。`data/schema.md` 屬於資料端的範圍，這類項目另外分一組，註明要交給資料端。

到這裡停下來，等使用者回覆要改哪幾項。

## 第二段：修改

只改使用者同意的項目，而且只改設計端可提交的檔案（`docs/`、`README.md`、`AGENTS.md`）。

- 在設計端目錄工作，照 `AGENTS.md`「開工與收工」的做法。
- 歷史紀錄不改寫：過時的事實在原處更正，必要時加上更正日期；不要刪掉描述當時狀況的段落。
- 只 `git add` 這次改的文件，不夾帶其他檔案。
- 跑 `npm run build` 確認通過，確認沒有把重產的 `data/` 檔案一起 stage。
- commit 後告訴使用者改了哪些項目，等使用者確認再推 `beta`。
